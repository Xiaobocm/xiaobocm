The Cost of Tokens Is Falling. The Cost of Bad Ideas Isn’t.

For most of the short history of commercial language models, the interesting constraint was access. A good model was expensive, rate-limited, or behind a waitlist. The question was whether you could get to it.

That constraint is loosening. Open-weight models are getting better. Inference is getting cheaper. Sparse architectures such as mixture-of-experts let a model hold far more parameters than it uses for any one token. The direction is clear enough: more intelligence, at a lower price per thought.

I think this is good news. I also think it quietly changes what the hard part is.

The price of a thought

A token is a small unit of work. When the price of a token falls, more kinds of work become economically reasonable: longer context, more attempts, more tool calls, more evaluation. The model does not have to be perfect on the first try if a second or third try is cheap.

But cheap tokens are not free intelligence. A model that routes a token through two experts instead of all of them still has to hold the others in memory. A long agent run still has to be orchestrated, observed, and stopped when it goes wrong. The bill moves: from the GPU-hour to the engineer-hour, from the inference API to the evaluation loop.

When a resource gets cheaper, the bottleneck does not disappear. It moves.

What MoE actually changes

Mixture-of-experts is an allocation trick. Instead of passing every token through every parameter, a router sends each token to a small subset of experts. The model can have a large total capacity while keeping the compute per token closer to a smaller model.

That sounds like a free lunch. It is not. Routing is a learned decision, and learned decisions can be wrong. Experts can become imbalanced. Communication and memory costs are real. The interesting research is not only “how big can we make the model?” but “how well can we spend the compute we have?”

def route(x, experts, k=2):
    scores = [expert.score(x) for expert in experts]
    top_k = sorted(range(len(scores)), key=scores.__getitem__, reverse=True)[:k]
    weights = softmax([scores[i] for i in top_k])
    return sum(w * experts[i](x) for w, i in zip(weights, top_k))

The sketch above leaves out the hard parts: batching, capacity limits, load balancing, and the fact that softmax has to exist somewhere. That is usually where the real system lives.

Agents spend tokens the way teams spend meetings

An agent is a model in a loop. It plans, calls a tool, reads the result, revises, and tries again. That loop is what makes agents useful. It is also what makes them expensive.

A single answer is one inference. A useful agent might be ten, fifty, or five hundred. It might carry a memory of the last attempt. It might keep several candidate plans alive. The cost is no longer a line item; it is a behavior.

Cheaper tokens make more ambitious loops possible. They do not make a bad loop good. An agent with no stopping condition and no evaluation is just a more expensive way to be unsure.

The scarce thing

If intelligence becomes cheap, what becomes expensive?

I think the answer is judgment. Choosing a problem that matters. Knowing what “better” means. Designing a system that fails safely. Noticing that the demo is impressive and the product is useless. These are not model capabilities. They are human ones.

This is why I keep coming back to ideas. In the AI era, we do not lack technology. We lack ideas worth pointing it at. A prompt is not an idea. A feature is not a product. An idea is a claim about what should exist, why it matters, and what trade-off is acceptable.

A small checklist

  1. Describe the problem without AI. If it is not a problem before the model, it will not become one after.
  2. Define the smallest useful demo. One user, one task, one measurable improvement.
  3. Write down the failure modes. What happens when the model is wrong, slow, or unavailable?
  4. Measure the loop, not the demo. Time saved, errors caught, decisions improved.
  5. Only then add scale. More tokens, more tools, more agents.

Cheap tokens are a wonderful excuse to think bigger. They are a terrible excuse to think less.

The cost of a token is falling. The cost of a bad idea is not. If anything, it is rising, because a bad idea now has more compute behind it.
