11-15-2026模型

Token 的成本正在下降，壞點子的代價不會

在商用語言模型這段不長的歷史裡，大部分時間真正有意思的限制條件是「能不能用到」。好模型很貴、有速率限制，或者得排隊候補。問題在於你有沒有辦法接近它。

這個限制正在鬆動。開放權重的模型越做越好，推論越來越便宜。像 mixture-of-experts 這類稀疏架構，讓模型可以擁有遠多於單一 token 實際用到的參數。方向已經夠清楚了：更多的智慧，每次思考的價格更低。

我認為這是好消息。我也認為，它正悄悄改變「難的部分」到底是什麼。

一次思考的價格

一個 token 是一小單位的工作。當 token 的價格下降，更多種類的工作在經濟上就變得合理：更長的上下文、更多次嘗試、更多工具呼叫、更多評估。如果第二次、第三次嘗試很便宜，模型就不必第一次就做到完美。

但便宜的 token 不等於免費的智慧。一個把 token 只送進兩個 expert、而非全部 expert 的模型，仍然得把其餘的專家留在記憶體裡。一次漫長的 agent 執行，仍然需要被編排、被觀察，並在出錯時被停下來。帳單只是換了位置：從 GPU 小時換成工程師小時，從推論 API 換成評估迴圈。

當某種資源變便宜，瓶頸不會消失，只會移動。

MoE 真正改變了什麼

mixture-of-experts 是一種分配技巧。它不讓每個 token 都穿過每一個參數，而是由 router 把每個 token 送給一小部分 expert。模型可以擁有很大的總容量，同時讓每個 token 的計算量接近一個更小的模型。

聽起來像免費午餐，但並不是。路由是一個學出來的決策，而學出來的決策會出錯。專家可能變得不均衡。通訊與記憶體成本是真實存在的。有意思的研究不只是「我們能把模型做多大？」，還有「我們能把手上的算力花得多好？」

def route(x, experts, k=2):
    scores = [expert.score(x) for expert in experts]
    top_k = sorted(range(len(scores)), key=scores.__getitem__, reverse=True)[:k]
    weights = softmax([scores[i] for i in top_k])
    return sum(w * experts[i](x) for w, i in zip(weights, top_k))

上面這段草稿漏掉了難的部分：批次處理、容量上限、負載平衡，以及 softmax 總得存在於某個地方這件事。真正的系統通常就住在這些地方。

Agent 花 token，就像團隊花會議

一個 agent 就是一個跑在迴圈裡的模型。它規劃、呼叫工具、讀取結果、修正，然後再試一次。這個迴圈讓 agent 有用，也讓 agent 昂貴。

一個答案是一次推論。一個有用的 agent 可能是十次、五十次，或五百次。它可能帶著上一次嘗試的記憶，也可能同時維持好幾個候選計畫。成本不再是一個預算項目，而是一種行為。

更便宜的 token 讓更有野心的迴圈成為可能，但不會把壞迴圈變成好迴圈。一個沒有停止條件、沒有評估的 agent，只是一種更昂貴的不確定。

稀缺的東西

如果智慧變便宜了，什麼會變貴？

我認為答案是判斷力。選擇一個真正重要的問題。知道「更好」是什麼意思。設計一個會安全失敗的系統。察覺到 demo 很驚人，而產品毫無用處。這些不是模型的能力，而是人的能力。

這就是我總會回到「想法」的原因。在 AI 時代，我們不缺技術，我們缺的是值得把技術指向的想法。一個 prompt 不是想法。一個功能不是產品。一個想法是一個主張：什麼東西應該存在、為什麼重要、什麼樣的取捨可以接受。

一份簡短的檢查清單

  1. 不用 AI 描述這個問題。如果它在模型出現之前不是問題，之後也不會變成問題。
  2. 定義最小可用的 demo。一個使用者、一個任務、一個可衡量的改善。
  3. 寫下失敗模式。當模型出錯、變慢或不可用時，會發生什麼事？
  4. 衡量迴圈，而不是 demo。省下的時間、抓到的錯誤、改善的決策。
  5. 到那時候才擴大規模。更多 token、更多工具、更多 agent。

便宜的 token 是思考得更大的絕佳藉口，也是思考得更少的糟糕藉口。

token 的成本在下降，壞點子的代價沒有。真要說的話，它還在上漲，因為現在一個壞點子背後有更多算力。
