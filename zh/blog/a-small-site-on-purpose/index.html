刻意做小的網站

這個網站是幾個 HTML 檔、一份樣式表、一個小小的 JavaScript 檔，加上一個裝圖片的資料夾。沒有框架、沒有資料庫、沒有建置流程。這不是限制，這是設計。

我想要一個能撐過忙碌學年的個人網站。一個我打開、編輯、發佈時不必先想起某套工具鏈的東西。一個在手機上載入很快，而且看起來仍然像是我願意待上一陣子的地方。

「靜態」換到了什麼

  • 長壽。2026 年寫的 HTML，2036 年還是能正常顯示。
  • 速度。沒有伺服器渲染、沒有客戶端 hydration、不用等執行環境。
  • 低維護。唯一的依賴就是這些檔案本身。
  • 可攜性。GitHub Pages 可以免費託管，任何靜態主機都能接手。

我放棄了什麼

沒有留言、沒有流量分析、沒有內容管理系統。我現在還不需要它們。如果哪天想要留言區，之後再加就好；如果想要分析，我可以挑一個對隱私友善的工具。從沒有這些東西開始，讓這個網站保持誠實。

新鮮的 HTML

靜態託管有個小問題：快取。GitHub Pages 不讓我設定自訂的 cache header。我發佈新頁面之後，訪客還是可能看到舊的。

所以網站做了三件事：請瀏覽器不要快取 HTML；每次載入時檢查一個小小的 build.json，如果部署的版本比較新就重新載入一次；再由一個 service worker 以 network-first 的方式處理頁面導覽。目標很簡單：我改了什麼，那個改變就要出現。

維護是一種設計限制

一個網站是一個小小的承諾：這個東西還會在那裡。守住這個承諾最好的方法，是讓網站容易修。樸素的檔案就是容易修。

這不是在反對框架。對很多工作來說，框架是正確的工具。這是在主張：選一個能承載這個想法的最小工具。

對個人網站來說，想法就是那些文字。其他一切都應該讓開。
